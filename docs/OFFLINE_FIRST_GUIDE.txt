# Journal — stockage local d’abord et synchronisation cloud sur consentement

Le journal doit rester utilisable hors ligne et la synchronisation cloud est
**désactivée par défaut**. Hive est la source de vérité locale ; les notes sont
stockées dans la box Hive chiffrée `hive.journal_entries.v1`.

## Consentement cloud

- Le choix de synchroniser est conservé localement dans `SharedPreferences` et lié au compte actuellement connecté ; un changement de compte ne transmet pas le consentement à l’autre compte.
- Ce choix est propre à l’appareil : un autre appareil doit lui aussi obtenir un opt-in. La suppression des copies cloud ne peut pas empêcher un autre appareil déjà autorisé de renvoyer ses notes.
- Aucune lecture ni écriture de notes dans Firestore n’est effectuée avant que
  l’utilisatrice n’ait accepté le dialogue de consentement.
- Le dialogue décrit les champs envoyés, précise l’absence de chiffrement de
  bout en bout par Peria et signale le cache hors ligne éventuel de Firestore,
  distinct de Hive.
- L’activation synchronise les notes locales et distantes ; les versions les
  plus récentes sont conservées.
- Désactiver la synchronisation bloque les prochains envois. Les copies déjà
  présentes dans Firestore ne sont pas supprimées automatiquement ; une action
  distincte permet de les supprimer, sans effacer les notes locales.
- Les suppressions locales sont gardées dans une box de tombstones chiffrée,
  afin qu’une synchronisation ultérieure ne restaure pas une note supprimée.

## Parcours d’une lecture

1. Lire la box Hive chiffrée et afficher son contenu.
2. Si le consentement cloud est actif, lancer ensuite une réconciliation
   Firestore en arrière-plan.
3. Si le réseau est indisponible, garder les données locales et afficher l’état
   de synchronisation comme incomplet/à réessayer.

## Parcours d’une écriture ou suppression

1. Mettre à jour l’état de l’interface de façon optimiste.
2. Persister d’abord dans Hive, sans attendre le réseau.
3. Si et seulement si le consentement est actif, ajouter l’écriture ou la
   suppression à la file cloud.
4. Afficher la date de la dernière synchronisation réussie et une erreur
   générique si la dernière tentative a échoué.

## Performance et état visible

- L’écran peut afficher un skeleton pendant l’ouverture initiale de Hive, mais ne doit
  pas attendre Firestore pour afficher les notes locales.
- Une actualisation ne doit pas vider la liste déjà affichée ; la réconciliation
  cloud reste en arrière-plan après le chargement local.
- La création, la modification et la suppression doivent rester rapides même
  hors ligne. L’état de la dernière tentative se consulte dans les réglages du journal.

## Tests manuels à réaliser

- Première installation : vérifier que le réglage cloud est désactivé et qu’une
  création de note ne déclenche aucun accès Firestore.
- Accepter le dialogue : vérifier la première fusion, puis créer, modifier et
  supprimer des notes.
- Refuser le dialogue : vérifier que le réglage reste désactivé et que les
  notes locales restent accessibles.
- Couper le réseau : vérifier que lecture et écriture locales continuent, puis
  réessayer une synchronisation lorsque le réseau revient.
- Désactiver après avoir synchronisé : vérifier qu’aucun nouvel envoi ne part,
  que la copie distante reste annoncée comme existante, puis tester la
  suppression explicite de la copie cloud.
- Supprimer une note et vider le journal hors ligne, puis réactiver la sync :
  vérifier que les tombstones empêchent la résurrection des anciennes notes.
- Mettre à jour depuis une ancienne version : vérifier la migration de l’ancien
  cache Map non chiffré vers la box Hive chiffrée, sans perte de notes.
